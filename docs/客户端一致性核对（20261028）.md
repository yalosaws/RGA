# 客户端一致性核对（2026-10-28）

目标是让程序计算遵循实际安装客户端的代码。本轮完成当前存档下的计算对照和关键运行时修复，**尚不代表所有构筑、所有时间状态及程序界面都已完成验收**。

后续界面与实时计算接入见《构筑辅助接入记录（20261028）》和《实时计算快照接入与验证（20261028）》。本页的逐方法核对数字与未覆盖范围继续有效，早期“尚未接入界面”不再代表当前进度。

## 本轮结果

| 核对项目 | 结果 | 范围 |
|---|---:|---|
| 原始字节码与 Python 返回值 | 4,193 个用例完全一致 | 3,339 个计算/判定方法；当前存档与若干参数样本 |
| 独立存档解码与实际载入状态 | 2,975 / 2,975 字段一致 | 建筑、升级、法术、统计、阵营币及关键全局状态 |
| AS3 语义回归 | 17 项通过 | 相等判断、真假值、整数/向量、Date、字节写入、读取修复等 |
| 游戏集成回归 | 10 项通过 | 购买、施法、费用/资源限制、隔离、平台状态与皇家贸易令查询表 |
| 计算与判定索引 | 3,529 个方法、1,422 个类 | 方法体完整保留，不截断公式；含尚未逐动作验证的入口 |

方法对照采用 `build/installed-pcode/scripts` 的指令，而不是再次运行同一份反编译源码。两次执行恢复相同对象状态和随机数位置。当前结果中没有数值差异、容差通过或执行错误；另有 **190 个状态变更入口明确标记为未核对**，不算通过。

解释器只直接解释正在核对的方法，子调用和 Math 仍使用 Python 对象/运行时。这是一种逐方法差分检查，不是完整 Flash VM，也不能单凭当前样本证明所有分支正确。

输入样本为 R44、A1、恶立场、恶魔/卓尔构筑的固定磁盘存档，文件摘要写在 `build/client-audit/final.json`。计算冻结在记录的样本时间；活动编号恢复自存档，未提供服务器活动缓存时使用空的离线缓存。服务器上下文缺失不等于真实游戏服务器数据为零。

## 已修正的问题

1. **反编译丢失了有副作用的读取。** `Game.load` 漏掉旧雪球大小的 `readUnsignedShort()`，后续字段错位 2 字节，佣兵法术、第二血统、购买模式等被误读。现在生成时先检查原始 pcode 的读取签名，再在内存中的 AS3 上恢复该操作；原导出文件不改。无匹配证据时停止生成。
2. **活动和时间不能作为界面桩。** 现在保留 PlayFab/TimeServer 的类型、默认字段和 getter/setter，服务动作不执行。修复 Date 的时间属性、本地/UTC 属性和日期构造；固定样本时间可传入。
3. **AS3 与 Python 的语义差异。** 区分 null/undefined，补齐普通/严格相等、空数组/对象真假值、参数及字段类型转换、int/uint 回绕、带类型向量初值与写入、字节写入低 8 位和 switch 的 default 落空顺序。
4. **无界面初始化遗漏查询表。** 皇家贸易令的相关表原本在界面初始化时填充。独立计算现在按同一规则从真实升级对象建立索引；Main 中计算所需的缓存与桌面平台常量有明确来源。
5. **失败不得悄悄变成零产出。** 缺少 Game/Core/Stats 时立即报错；关键类解析/修复失败不继续生成；即时试算要求模块关联原始 pcode，避免旧的未核对模块继续误算。

## 关于两套导出的纠正

两套 AS3 导出共有 2,488 个同路径文件，其中 8 个文本不同。对这些类逐方法比较 pcode 后，**没有发现方法体指令变化**。因此，之前把最大魔力分支差异解释成客户端新增公式，没有充分依据；本次证据表明它们属于反编译输出差异。

这项比较没有证明整个 SWF、常量池、资源或字段初值都相同。后续必须用原始字节码和内容摘要约束来源，不能只看反编译文本，也不能用旧截图的小百分比误差宣称已经精确一致。

## 可复跑的入口

```powershell
python -X utf8 -I scripts/as2py.py build/installed-as3-deobf/scripts build/rg_installed_game.py --pcode build/installed-pcode/scripts --swf "D:/steam/steamapps/common/Realm Grinder/RealmGrinderDesktop.swf"
python -X utf8 -I scripts/test_as_semantics.py
python -X utf8 -I scripts/test_rg_sim.py build/rg_installed_game.py build/production-check3.sol
python -X utf8 -I scripts/client_audit.py build/installed-pcode/scripts build/rg_installed_game.py --save build/production-check3.sol --output build/client-audit/final.json
node scripts/decode_save_audit.cjs build/production-check3.sol build/decoded-snapshot.json
python -X utf8 -I scripts/client_save_audit.py build/rg_installed_game.py build/production-check3.sol build/decoded-snapshot.json
python -X utf8 -I scripts/client_catalog.py build/installed-pcode/scripts build/installed-as3-deobf/scripts build/client-audit docs/客户端计算方法索引（实际安装版）.json
```

更换客户端后，必须先重新导出该 SWF 的 AS3 和 pcode；不要把上面两个目录当作自动更新的游戏源。模块旁的 `.manifest.json` 记录 SWF/源码摘要、修复证据和未转写文件。

新索引 `客户端计算方法索引（实际安装版）.json` 保留完整方法体、参数、来源、指令摘要及样本核对次数。旧规则表仍可作为历史资料，不能据此宣称旧提取结果已全部与本次索引对齐。
