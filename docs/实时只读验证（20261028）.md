# 实时只读验证（2026-10-28）

已完成本机游戏进程的小范围读取，并接到源码程序“工具 → 实时读数”。本轮不打包、不发布。

后续已增加构筑辅助的实时计算快照，见《实时计算快照接入与验证（20261028）》。本页描述轻量读数接口。

## 本次读到什么

目前对正在运行的 32 位 `RealmGrinderDesktop.exe` 读取：金币、魔力、25 种建筑数量与 32 项法术状态。验证时魔力 6421，非零建筑为农场 4190、旅馆 4105、铁匠铺 4052；与当时完整存档中这些稳定字段一致。金币在连续采样间增长，不依赖游戏把新存档写到磁盘。

多次独立连接均重新定位到同一主对象；首次定位约 1.5～2 秒，随后每次完整读出这组字段约 5～8 ms。程序约每 200 ms 请求一次，不重复整片扫描；界面只在本次请求结束后安排下一次，避免请求堆积。

初次样本法术均未激活。后续用户手动开启法术后，已读到 5 项持续法术的激活状态和按 30 tick/秒推进的计时；用户重启游戏后也成功重新定位了一次。轻量读数接口本身不提供完整计算输入。

## 如何排除误命中

- 初次按存档中的建筑数字搜索，只能得到候选：曾命中的是建筑对象中的其他统计字段，不能直接把它当作当前建筑数。
- 后续按客户端的当前数量 getter 定位到其独立的 uint 数值对象；核对对象类型、构造参数、数值校验关系、存档 ID 和主游戏向量，才确认当前数量。
- 魔力按客户端独特构造参数和类型识别，再沿引用找到主类对象。金币、建筑和法术从这个主对象的字段读取，不采信同值的界面字符串或失效对象。
- 数值从 `v/c/f` 字段及校验关系共同验证；读取中对象引用或写入状态变化时重试，未取得有效值就报错，不用零值掩盖失效地址。
- 对象布局参考 [Adobe 开源 AVMplus 类型定义](https://github.com/adobe-flash/avmplus)，并按当前进程实际结构验证；没有执行游戏 VM 中的 getter，因此也不增加游戏 getter 自己的检查计数。

## 范围与控制

仅申请 `PROCESS_QUERY_INFORMATION | PROCESS_VM_READ`（0x410）。目标必须是 `RealmGrinderDesktop.exe`，且 SWF 与已核对模块的 SHA256 一致，加载的 AIR DLL 也须与本轮布局档一致。没有写入、注入、暂停游戏线程、改变内存页权限或绕过访问拒绝。没有扫描其他进程的内存，没有保存原始内存页转储；本地验证记录只保存指定业务字段、布局及命中地址。

各个数值对象分别通过一致性校验，但没有暂停游戏，因此不能保证金币、魔力与所有其他字段都属于同一个逻辑 tick。此接口不是可直接送入完整计算引擎的全量状态。

界面默认不自动开始；点击“开始读取”后连接，点击“停止读取”、离开本页或页面隐藏时停止。停止请求会先设置取消标志，再等待锁，初次扫描也能中断；关闭进程句柄后保留的数字明确标为上一次读数。构筑辅助可选择完整存档或另行采集的实时计算快照，不混用轻量读数和旧存档上下文。

## 文件

- `scripts/game_memory_probe.py`：限定游戏进程的 Windows 只读访问、区域查询与有限模式定位。
- `scripts/avm2_memory.py`：当前 32 位 AIR 的对象、字符串、向量与受校验数值解析。
- `scripts/read_game_live.py`：主对象定位、版本校验及有限字段采样；每次新连接重新定位，不使用上次保存的绝对地址。
- `docs/只读内存布局（当前安装版）.json`：SWF/AIR 哈希与已确认字段布局。
- `app/live_reader.py`：进程选择、单连接管理及取消。
- `scripts/live_tools.html/js`：只读验证入口；数据与存档试算分开显示。
- `build/live-read-validation.json`：本次进程的结构化采样，仅作验证记录。

命令行复测（替换为当时正在运行的游戏 PID）：

```powershell
python -X utf8 scripts/prepare_engine.py
python -X utf8 scripts/read_game_live.py <PID> --samples 10 --interval 0.1
```
