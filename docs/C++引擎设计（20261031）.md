# C++ 计算引擎设计（2026-10-31，已接入「按目标找 build」）

## 目标

「按目标找 build」和「连续模拟」的时间几乎全花在**整局跑**上。实测 60 秒游戏时间要跑 38.6 秒，其中：
- 推进 tick 约占 31.8 秒；
- 每次买东西后清缓存、重算全部产出，118 次共 18.8 秒；
- 重算点击值，117 次共 13.2 秒（和上一项有重叠）；
- 「全部购买」30 次共 5.3 秒。

用户要求直接做 C++，目标是快 30～100 倍，并且和 Python 版逐 tick 对得上。以后有需要再加「事件跳跃」的近似粗筛，目前不做。

## 运行时要点（rt.h）

### 值和字符串
- `Value` 共 16 字节，标签有 UNDEF、NULL、BOOL、NUM（double）、STR、OBJ。
- **没有单独的整数标签**：Python 版区分 int 和 float，C++ 全用 double，和 Flash 一致。所以在超过 2^53 的整数运算上，两边最后几位可能不同，对照时要允许极小误差。
- 字符串 `Str` 是不可变的 UTF-16。字面量永久存放；运行中新建的字符串放在内存池里。

### 对象
- 对象 `Obj` 带 `ci`（ClassInfo）和可选的 `dyn`（`DynMap`，存运行时动态加上的属性）。
- 种类有：生成的实例 `K_INST`，以及 ARR、VEC、DICT、FUNC、CLASSREF、BYTES、DATE、REGEXP（占位）、ERROR、STUBVAL、STUBINST、HEADLESS、SO。
- `Pod` 是字段全为 POD 的对象，快照时整块复制字段区；生成的类的根 `Inst` 继承自 `Pod`。
- `Dict` 按插入顺序存。键的规则同 Python：1、1.0、True 是同一个键；字符串按内容比；对象按身份比。
- `isa` 是 O(1) 判断：比较 `depth` 和 `anc[]`。

### 内存池和快照
- 一局只新建约 1300 个临时对象，所以**不用引用计数**。所有对象都分配在内存池里，并登记在 `W->objs`。
- `World::snapshot()`：对已有对象逐个 `snap_save`，再复制登记过的静态区、RNG 和 CLOCK。
- `restore()`：析构快照之后新建的对象，内存池退回快照时的位置，再把字段写回去。对象身份保持不变，Python 代理持有的指针一直有效。
- **一个进程只能有一份游戏**：静态区是全局的。worker 本来就是一进程一份，没问题。

### 和 Python 版一致的语义（照抄 as_runtime）
- `T()` 判断真假时 NaN 为假；`pybool()`（Python 自己的 `and`/`or`）判断时 NaN 为真，STUB 为假，空数组为真。
- `add`、`eq`、`strict_eq`、`lt`、`le`、`tostr`、`tonum`、`toint`（任意 double 都按 ToInt32 精确取模）的规则同 Python 版。
  - `tostr` 规则：整数值且绝对值小于 1e21 时输出全部数字；其余按 Python repr 输出，即小数点位置 `decpt <= -4 or > 16` 时用科学计数法，指数至少两位。
- **STUB**（没转写的东西）：取属性、调用都得到自己，判断为假；数值上当 0 用。
- `new 未知类()` 得到 STUBINST：判断为真，取属性得到 STUB。
- **HEADLESS**（界面替身）：取属性得到 NOOP 函数（判断为真），调用返回 null；赋值存进 `dyn`，之后读回的是存进去的值。
- `idx_get`（下标取值）：
  - 数组：小数取整，越界或 NaN 得到 UNDEF；字符串下标按整数解析。
  - 字典：按键取。
  - null：抛 Thrown。
  - 字符串：取单个字符。
  - 其他对象：键是字符串时按名字取属性，取不到得到 null。
- `Arr.sort(fn)`：fn 不是函数时（例如传了 Array.NUMERIC），Python 版**按字符串排序**；用稳定排序。
- `Math.round(x)` 等于 `floor(x+0.5)`；`Math.max`/`Math.min` 只要有 NaN 就返回 NaN。
- 随机数：`RNG` 是 MT19937 加 `genrand_res53`，和 Python `random.random()` 逐位相同。初始状态要从 Python 的 `random.getstate()` 传进来（Runner 先 `random.seed(seed)`，再创建游戏）。
- 时钟：`CLOCK.timestamp`（秒）和 `CLOCK.timer_ms`。`new Date()` 用 timestamp；`getTimer()` 用 timer_ms（是小数）。本地时间用 `_localtime64_s`。
- `SharedObject.getLocal()`：返回的 SO 里，`data` 是 `{'save': SO_SAVE_TEXT}`。

### 内建名字
- 内建名字 id 是 0..NB_BUILTIN-1，见 rt.h 的枚举，顺序和 rt.cpp 的 `BUILTIN_NAMES` 一致。
- 生成代码的名字从 NB_BUILTIN 往后排，由 `register_names` 注册。

## 转写器设计（as2cpp.py，待写）

### 输入
- `as2py.convert_dir('build/installed-as3-deobf/scripts', pcode_root='build/installed-pcode/scripts')`，得到 1884 个文件、1886 个类、约 9300 个函数。
- 再加上辅助类的 AS3 源码（见下文）。
- 只生成 `kind == 'class'` 的类，接口当动态值处理（全工程只有 1 个接口）。

### 命名
| 对象 | C++ 名 |
|---|---|
| 类 | `C_` + mangle(短名) |
| 字段 | `f_` + mangle_attr |
| 实例方法 | `m_` |
| getter / setter | `g_` / `s_` |
| 静态方法 / 静态 getter / 静态 setter | `sm_` / `sg_` / `ss_` |
| 局部变量 | `l_` |
| 名字 id | `NM_` + mangle_attr；内建名字用 `rt::N_xxx` |

反射用的名字字符串是 `mangle_attr`，和 Python 版的属性名一致。

### 类型
- int → `int32_t`，uint → `uint32_t`，Number → `double`，Boolean → `bool`。
- 其余（String、类、Array、Vector、Object、`*`、无类型）一律存成 `rt::Value`。
- 推断时还会区分 `('C', 类名)`、`'A'`、`('VEC', 元素类型)`、`'S'`，用来选快速路径。

### 类型转换只在 Python 版做转换的地方做
- 有类型声明的局部变量赋值时（含 `+=`）；
- 参数入口；
- return（按声明的返回类型）；
- 字段赋值时（类型化字段）；
- Vector 元素赋值时。
- 转换函数：int → toint，uint → touint，Number → to_number，Boolean → T，String → slot_string（null 或 undefined 得到 null，其余调用 tostr）。
- **不转换的地方**：类类型字段（原样存）、for-in 循环变量、表达式里的 `++`/`--`。

### 局部变量默认值（同 as2py.default_for）
| 类型 | 默认值 |
|---|---|
| `*` | UNDEF |
| int / uint | 0 |
| Number | NaN |
| Boolean | false |
| 其余，**包括没写类型的** | null |

参数被 `var` 重新声明时不重置。缺省参数的默认值：I/U 是 0，N 是 NaN，B 是 false，S 是 NUL，其余是 UNDEF。

### 成员访问
- 静态类型已知是 C 类时，走快速路径：`rt::rd<C_X>(v, id, [](C_X* p){ return p->f_x; })`。对不上时（界面替身、桩、null），按名字走 `rt::dget`。
- 写字段用 `rt::wr`，调方法用 `rt::mc`（对不上时把参数装箱，走 `dcall`）。
- 对 `this` 直接访问，不做检查。
- `super.x` 用限定名做非虚调用：`this->C_Base::m_x()`。
- 在类继承链上查找时，每层的顺序是：getter/setter → 字段 → 方法。查到外部类（界面库）时当未知处理，走动态访问。
- 静态成员：名字在 STATIC_PROP_NAMES 里（某处有同名静态 getter）时，先找链上的静态变量，再找静态 getter；否则逐层找静态变量或静态方法。
- `length`：数组、字符串直接取长度；类上有 `length` getter 就调用它；其余走 `rt::alen`。
- 方法名在 STR_METHODS 里、但对象不是 C 类型时，走 `rt::mcall`。

### 虚函数签名
- 同名方法在继承链上统一用**最上层声明的参数和返回类型**。
- 子类自己声明的类型不同时，在入口和返回处转换。

### 构造（同 as2py.gen_class）
- 有构造函数，或者有任何实例变量声明，就生成自己的 `ctor_X`。
- 字段初值：常量直接写成 C++ 成员默认初值；非常量放在 `pre` 里。
- 执行顺序：
  - 构造函数体里有 `super(...)` 时：`pre` 在函数体之前；
  - 有父类但没写 `super()` 时：先 `父类 ctor()`，再 `pre`，再函数体。
- `super()` 调用离得最近的、有自己 ctor 的祖先；都没有时什么也不做。
- `new X(args)` 等于分配对象，再调用最近一个有 ctor 的类（X 自己或祖先）。
- 调用 `X(args)`（当函数调用）时，Python 版会**新建实例**，C++ 照做。
- 子类重新声明了父类字段时，不新开存储，在 newobj 里覆盖默认值。会把这种情况列出来。

### 反射（每个类生成）
- `dget`：getter → 字段 → 方法（返回绑定函数）→ 父类。
- `dset`：字段（转换类型）→ setter → 父类；只有 getter 没有 setter 时返回 false。
- `dcall`：方法（参数用 `rt::arg<T>` 转换，缺的补默认值）→ 存着函数的字段或 getter → 父类。
- 静态侧生成 `sget`、`sset`、`scall` 挂到 ClassInfo 上，运行时沿 parent 链找（同 Python MRO）。
- 实例上找不到成员时，还要查类的静态成员（Python 版通过实例能读到类属性）。**rt.cpp 的 `dget` 里 K_INST 分支还没加这一步**。
- 类本身作为值：每个类一个永久的 `ClassRef`。

### 静态区
- 全部放进一个全局结构 `ST SV`，用 `register_statics` 登记，快照时整块复制。
- 默认值由生成的 `st_defaults()` 赋值，不写成员默认初值，因为字面量表要先初始化。
- `static_init()` 按 as2py 的 `order`（父类在前），每条初始化语句单独包 try/catch，出错就记下来继续。

### 语句
| 语句 | 写法 |
|---|---|
| for | 增量部分用 GNU 语句表达式 `({ ... })` |
| for-in / for-each | 先用 `rt::keys`/`rt::each` 拷贝出列表再循环 |
| switch | 先按 `strict_eq` 依次比较算出入口，再用 C++ switch 加穿透 |
| try/catch | 同时捕获 `rt::Thrown` 和 `rt::RtError`（Python 版的 `except Exception` 两类都捕获），catch 体复制两份 |
| finally | 只有 1 处（界面代码）：`catch(...){fin;throw;} fin;` |

- 没有标签跳转、逗号表达式、嵌套函数声明。
- 匿名函数只有 3 处，都在界面代码里，生成为 NOOP。
- 正则只出现在 adobe 库里，用占位对象代替。
- `&&`/`||` 按 Python `and`/`or` 返回操作数：用 `pybool` 选择，两边类型不同时都装箱成 Value。在条件里：`T(a and b)` 等于 `pybool(a) && T(b)`；`T(a or b)` 等于 `pybool(a) ? T(a) : T(b)`。
- 算术运算都按 double 做（uint 减 1 不能回绕）。位运算先转 int32。
- 掉出函数末尾或 `return;` 时，Python 返回 None。C++ 按返回类型给值：N 是 0，I/U 是 0，B 是 false，Value 是 NUL。void 方法当值用时得到 NUL。
- 字面量：数字一律写成 double；字符串放进一个大的 char16_t 数组加偏移表 `LS[]`，按下标取。

### 名字解析顺序（同 as2py.resolve_name）
1. 局部变量；
2. 类名，或 BUILTIN_NAMES 里的内建名（Math、Number、int、String、Array、Vector、Date、Error、ByteArray、Dictionary、isNaN、trace、getTimer、`_`、`_n`、parseInt……）；
3. 当前类的成员（lookup_member）；
4. 其余当作没转写的全局名，按 STUBCLASS 处理。特殊的是 `SharedObject`，它的 getLocal 返回 SO。

## 已知差异和注意

- 没有单独的整数类型：超过 2^53 的整数运算最后几位可能和 Python 版不同（目前对照里没遇到）。
- 函数实参、二元运算两边的求值顺序 C++ 不保证（clang 实际是从左到右）；对照里没遇到差异。
- `is int` 按数值是不是整数判断（Python 版看类型）；游戏代码里没用到。
- 类上动态挂的属性（`constructor["id"] = …`）按 Python 规则只写这个类自己、读时沿继承链找；但编译时就解析成父类静态字段的读法不会看到子类后挂的同名属性（游戏里每个升级类都自己声明了 `id`，不受影响）。
- 一个进程只能启动一份原生游戏。
